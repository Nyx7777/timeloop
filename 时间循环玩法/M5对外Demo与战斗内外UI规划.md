## 1. M5 目标

M5 不只是增加几场战斗，而是把已经验证的战斗纵向切片组织成一段可以交给陌生玩家、无需开发者讲解的完整产品体验。

对外 Demo 的完整闭环为：

`标题/继续 → 本轮准备 → 路线地图 → 节点详情 → 战斗 → 战后结算 → 奖励/Build 选择 → 返回地图 → 事件/资源节点 → Boss → 本轮总结/合并回放`

M5 的宏观设计遵循 D-035：本作不是典型肉鸽，而是“时间循环战术解谜冒险，带有轻肉鸽路线与构筑”。首个 Demo 只验证一轮内的路线、Build 和 Boss 闭环；完整游戏再用有限章节循环承载“探索未知 → 利用已知 → 历史重演压缩旧内容”。不把无限随机周目、完整商店经济、强追兵或传统数值 Meta 当作 M5 的默认目标。

本阶段同时解决两类缺口：

1. 战斗内：把 M4 已验证的交互骨架升级为正式 UI，并补齐固定敌人意图、扰动与清醒的信息表达。
2. 战斗外：建立路线、节点、奖励、Build、事件、Boss 和本轮结算组成的最小闭环。

M4 保持“已验收结项”。M5.0 是对既有战斗表现的产品化，不回滚 M4 的规则、动画和布局成果。

## 2. 统一 UI 设计系统

战斗内外界面共用同一套视觉语言，避免先分别制作、再被迫返工统一：

- 字体层级：标题、关键数值、正文、辅助说明与警告文字。
- 面板体系：顶部栏、普通卡片、弹窗、节点详情、奖励卡和 Boss 信息条。
- 图标体系：时间线、命数、回合、固定历史、扰动、清醒、奖励和资源。
- 按钮状态：默认、按下、选中、禁用、锁定、教程聚焦。
- 颜色语义：青色代表本体与可操作，紫色代表分身与录像，橙色代表固定历史，红色代表伤害危险，金色代表清醒或脱离固定历史。
- 动效语义：普通交互、锁定、断裂、清醒、获得奖励和关卡完成使用不同节奏。
- 可访问性：重要信息不能只依赖颜色；同时使用轮廓、图标、文字或动态中的至少一种辅助编码。

### M5.0B：固定意图、扰动与清醒信息系统

目标：让玩家在不读日志的情况下，快速理解每个敌人的时间状态及本回合行为。

当前进度（2026-08-09）：

- 新增表现层 `EnemyIntentPresentation` 只读快照；所有信息来自 `BattleState.locked_enemy_intents`、单位顺序和敌人状态，不建立第二套意图或清醒真相。
- E 编号按关卡完整敌人顺序稳定映射，敌人死亡不会使其余编号重排；用户首轮反馈后，编号只保留在顶部行动卡，棋盘不重复显示，以降低叠层噪声。
- 固定与待醒敌人已接入橙色逐格虚线路径、终点、从移动后终点发出的红色攻击线/危险格、伤害和等待徽记；“X伤”“等待”和待醒信息保留在单位上层。
- 行动卡已可点击聚焦：被选敌人保持完整不透明度，其余敌人意图降至 20%，再次点击取消；行动卡同步显示选中状态。
- `enemy_disturbed` 已接入断裂时钟双环/碎片波纹；当前回合提示“本回合仍锁定”并保留旧意图，待醒徽记明确下回合切换。
- 清醒敌人只显示金色特殊行动卡与棋盘 `?`；其表现快照不包含路径、攻击目标或伤害，防止泄露实时 AI。
- 223 项核心测试与 293 项界面/动画测试通过；新增 T2 本体位移在 T3 由 T2 分身重建时不重复扰动的正常结束与立即结晶回归。

门禁结果：用户已确认棋盘信息减法、行动卡聚焦、伤害/等待、扰动/清醒三段时序及 T3 历史位移修正均无问题；M5.0B 正式关闭，进入 M5.0C。

固定敌人显示：

- 每名敌人在行动序列中拥有稳定编号，如 E1、E2；棋盘不重复绘制编号，通过点击行动卡后的路径聚焦对应敌人。
- 棋盘显示从敌人当前位置出发的橙色虚线路径、移动终点标记，以及从移动后终点发出的红色攻击线/危险格与伤害信息。
- 固定等待行为使用沙漏或“等待”标记，不能表现成无信息。
- 固定历史使用完整时钟徽记；多个意图重叠时，点击行动序列中的敌人头像可单独聚焦该敌人，其余意图降低透明度。

扰动与清醒分三段表达：

1. 扰动发生瞬间：播放断裂时钟波纹；显示“已扰动·本回合行为仍已锁定”。
2. 当前回合剩余阶段：保留该敌人的既定意图，并显示“下回合清醒”过渡徽记，避免玩家误以为当前行动已改变。
3. 下一回合起：敌人改用金色断钟/清醒状态，行动序列使用特殊边框；不再显示固定意图，棋盘以 `?` 表示其将在玩家行动后按实际战场重新决策。

顶部状态不再只显示全局“已知/未知”，而是提供类似“固定 2 · 清醒 1”的简洁汇总。规则语义保持不变：扰动不改变本回合已锁定行为；敌人下一回合清醒，在当前时间线持续实时决策，时间线结束后把新行为写入固定历史。清醒不跨时间线继承；进入下一条时间线后，新历史先重新固化。分身重演的位移如果在全部分身行动结束后成功还原该历史回合记录的“敌人阶段前实际位置”，不算扰动；该位置包含上一条时间线由本体已经建立的位移，因此 T3 中 T2 分身准确重建 T2 位移不会再次唤醒敌人。只有重演结果偏离历史，或本体随后造成新的有效干涉，才重新触发“待醒→清醒”。

- 六关可玩，现有 223 项核心测试与 293 项界面/动画测试不得回退；新增状态需加入表现回归。

### M5.1：战斗外 UX 流程与页面规格

先做低成本流程图和线框，再生产正式美术。覆盖：

- 标题/继续与新游戏。
- 本轮准备或最小战前配置。
- 路线地图、节点状态和节点详情。
- 路线节点至少预留未知、已知、已访问、可历史重演和历史偏移五类信息状态；首个 Demo 可以只实际使用前三类，但流程与组件不能阻断后两类扩展。
- 战斗结果、奖励/Build 选择与返回地图。
- 事件/资源节点。
- Boss 进入提示。
- 本轮成功/失败总结与合并回放入口。
- 完整章节未来还需覆盖区域重置、保留知识摘要、旧路线快速重演与主动改走新路线；M5.1 先做低成本远期状态线框，不要求 M5.3 首轮全部实现。

第一版结构候选已记录在《M5.1 战斗外 UX 流程与页面线框》：

- 旧 08—13 六张 UI 稿全部早于 D-035，不再决定战斗外产品结构；13 号只保留为战斗视觉基准，14 号继续提供已验收共享组件语言。
- 固定六节点地图为教学战 → 二选一普通战 → 汇合事件/资源 → 精英 → Boss，单次路线访问五个节点。
- 地图作为唯一战斗外枢纽，节点详情使用底部抽屉；战后结算与奖励采用同页两阶段。
- 节点状态拆成知识、进度、历史、可达四条组合轴，远期预留“历史重演”和“历史偏移”。
- 首版只保留空间、行动、时间三个模块槽，至少实装两类；第二武器与监视延期。
- 坍缩只在地图、战后结算和本轮总结显示，不作为追兵倒计时或战斗难度惩罚。
- 合并回放首版只覆盖 Boss 获胜战，提供 `1× / 3× / 跳过`。

门禁：所有页面能串成可点击流程，返回路径、取消路径和失败路径明确；战斗外 UI 必须复用 M5.0A 的组件语言。

### M5.2：RunSession 与数据骨架

建立一轮游戏的唯一权威状态，至少包含：

- 路线图、当前节点、已访问/可访问节点和节点结果。
- 当前 Build、背包/资源、坍缩值与待领取奖励。
- 战斗开始前的输入和战斗结束后的结算输出。
- 可序列化的本轮状态，为继续游戏、失败恢复和测试复现留接口。
- 明确 `RunSession` 与跨轮章节记忆的边界：节点知识、Boss/敌人情报、捷径和历史解法不应混入本轮临时 Build；可以先定义只读接口或数据占位，不提前完成完整 Meta。
- 为历史重演保留节点版本、关键开局条件、录像引用与“历史偏移”原因；具体一致性判定和奖励防重抽在实现前单独裁决。

此阶段先确定数据与页面的边界，不提前搭建完整商店、Meta 或多章节框架。

### M5.3：最小宏观闭环

实现并打通：

`路线选择 → 节点进入 → 战斗 → 战后结算 → 奖励选择 → 返回路线 → 事件/资源节点 → Boss`

验收以一轮连续游玩为准，不再依靠开发菜单手工跳关来模拟产品流程。

M5.3 不要求为了展示循环而设置强制 Boss 失败，也不要求实现整章永久失败。普通战失败默认返回当前节点重试；完整区域重置与历史重演可以在后续里程碑接入。

### M5.4：首个对外 Demo 内容

推荐首轮规模为 6 节点左右：

- 1 个开始/教学节点。
- 2 个形成路线选择的普通战节点。
- 1 个事件或资源节点。
- 1 个汇合后的普通战或精英节点，用于检验 Build 成型后的战斗。
- 1 个 Boss 节点。
- 贯穿流程的 3—5 个奖励/强化选择，以及通关后的合并回放。

第一版原则上延期：完整商店经济、动态追兵、Meta 成长、多章节内容。D-036 候选同时延期第二种武器与监视，坍缩只做长期信息显示，合并回放只覆盖 Boss 获胜战；以上范围在 M5.1 走查中确认。

首个 Demo 的 20—30 分钟不是完整游戏单轮时长样板。正式游戏目标为首通 6—9 小时、可选完成约 10—15 小时；暂按序章、三个章节和终章估算，每章允许 1—3 次有意义的区域循环。M5.4 只需证明“一场奖励会改变下一场战斗的时间线解法”，不提前生产完整章节的随机内容量。

### M5.5：无讲解对外验证

- 邀请未接触项目的玩家从标题页开始独立完成体验。
- 观察是否能理解路线目标、奖励选择、时间循环、固定意图、扰动清醒、失败代价和最终目标。
- 记录完成率、卡住位置、错误理解、单次时长和是否愿意继续玩。
- 只根据高频理解问题和阻断问题调整，不在测试中临时扩张范围。

## 4. M5.1 走查前仍需确认的范围项

下列项目已有第一版候选，但必须在进入 M5.2 前由用户走查确认：

- 第一轮外测暂定面向有战术/解谜经验的陌生玩家，使用私密 Windows Godot 竖屏测试包；Android 真机触控后置。
- 路线暂定六个物理节点、单次访问五个，使用一处分支与一次汇合。
